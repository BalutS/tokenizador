========================================================================
EXPLICACIÓN DETALLADA DEL PROYECTO: ANALIZADOR LÉXICO PARA C SIMPLIFICADO
========================================================================

1. VISIÓN GENERAL DEL PROYECTO
------------------------------------------------------------------------
Este proyecto es un Analizador Léxico (Escáner / Lexer) escrito en Java para
un subconjunto del lenguaje de programación C. Su objetivo principal es
transformar una secuencia de caracteres de código fuente en una secuencia
ordenada de "Tokens" (los componentes léxicos básicos como palabras clave,
identificadores, operadores, literales de texto/números y delimitadores).

El diseño está implementado sin librerías externas de lexing (como Lex/Flex)
ni expresiones regulares del lenguaje. En su lugar, utiliza un Autómata Finito
Determinista (AFD) con una tabla de transiciones bidimensional explícita y la
técnica clásica de simulación de AFD mediante "maximal munch" (coincidencia más
larga) con retroceso (rollback).


2. FLUJO DE ENTRADA Y PROCESAMIENTO PASO A PASO
------------------------------------------------------------------------
El flujo completo de ejecución sigue los siguientes pasos:

1) Entrada por Línea de Comandos:
   El usuario ejecuta el programa pasando la ruta de un archivo de código C:
   `java Main programa.c`

2) Carga e Inicialización (Clase Main):
   - El método `Main.main` recibe los argumentos y lee todo el contenido
     del archivo especificado en un objeto `String` usando `Files.readString()`.
   - Se crea una instancia de la clase `Lexer` pasando dicha cadena de texto.

3) Solicitud Repetitiva de Tokens (Bucle Principal):
   - `Main` entra en un bucle continuo donde llama iterativamente al método
     `lexico.siguienteToken()`.

4) Limpieza de Espacios y Comentarios (Clase Lexer):
   - Antes de iniciar la lectura de un token, `siguienteToken()` invoca a
     `omitirEspaciosYComentarios()`.
   - Este método descarta espacios en blanco (' '), tabulaciones ('\t'), saltos
     de línea ('\n', '\r'), comentarios de una sola línea (`//...`) y comentarios
     multilínea (`/*...*/`), manteniendo actualizado el contador de líneas.

5) Simulación del AFD y "Maximal Munch" (Método `escanearConTabla`):
   - El Lexer toma el carácter actual y determina su "clase de carácter" (columna)
     usando `clasificar(char c)`.
   - Comienza desde el estado inicial (`INICIO` = 0) y consulta la tabla de
     transiciones (`tabla[estadoActual][clase]`).
   - Si la transición es válida (diferente de `MUERTO`), avanza en el texto y pasa al
     siguiente estado.
   - Si el nuevo estado es de aceptación (indicado en el arreglo `aceptacion`), el Lexer
     recuerda este estado y la posición en el texto como "última coincidencia válida".
   - Continúa consumiendo caracteres mientras existan transiciones válidas para
     lograr la coincidencia más larga posible ("maximal munch").

6) Retroceso (Rollback) y Generación de Token:
   - Cuando se alcanza un "estado muerto" (`MUERTO`), el proceso de avance se detiene.
   - Si se registró al menos un estado de aceptación previo, el Lexer retrocede
     su puntero de lectura hasta la posición de esa última coincidencia válida.
   - Extrae el texto fuente equivalente al lexema reconocido.
   - Si el token reconocido fue identificado genéricamente como un identificador
     (`TipoToken.IDENTIFICADOR`), se consulta el mapa `PALABRAS_RESERVADAS` para
     verificar si corresponde a una palabra reservada del lenguaje (como `if`,
     `while`, `int`, etc.).
   - Se crea y retorna un objeto `Token` con su tipo, lexema y línea inicial.
   - Si no se alcanzó ningún estado de aceptación, se genera un token de tipo
     `TipoToken.ERROR` indicando el símbolo no reconocido.

7) Impresión y Finalización (Clase Main):
   - `Main` recibe cada token e imprime en la salida estándar el resultado con el
     formato: `Token: TIPO "lexema"`.
   - Si se encuentra un token de tipo `ERROR`, se reporta por salida de error estándar.
   - El proceso finaliza cuando el `Lexer` retorna el tipo de token `TipoToken.FIN_ARCHIVO`.


3. EXPLICACIÓN DETALLADA DE CADA CLASE Y SUS MÉTODOS
------------------------------------------------------------------------

------------------------------------------------------------------------
A. Clase `TipoToken` (enum en TipoToken.java)
------------------------------------------------------------------------
Define todos los tipos de componentes léxicos posibles que puede reconocer el escáner.

Categorías principales de valores enum:
- Palabras Reservadas Principales: INT, MAIN, VOID, BREAK, DO, ELSE, IF, WHILE,
  RETURN, READ (scanf), WRITE (printf).
- Palabras Reservadas Adicionales de C: AUTO, DOUBLE, STRUCT, LONG, SWITCH, CASE,
  ENUM, REGISTER, TYPEDEF, CHAR, EXTERN, UNION, CONST, FLOAT, SHORT, UNSIGNED,
  CONTINUE, FOR, SIGNED, GOTO, SIZEOF, VOLATILE, STATIC, DEFAULT.
- Operadores y Símbolos Especiales:
  * Delimitadores: LLAVE_IZQ ({), LLAVE_DER (}), CORCHETE_IZQ ([), CORCHETE_DER (]),
    PAREN_IZQ ((), PAREN_DER ()), PUNTO_Y_COMA (;), COMA (,), PUNTO (.), FLECHA (->).
  * Aritméticos / Bits: MAS (+), MENOS (-), MULTIPLICACION (*), DIVISION (/), XOR_BIT (^), NOT_BIT (~).
  * Lógicos y Relacionales: AND_BIT (&), OR_BIT (|), NOT_LOGICO (!), ASIGNACION (=),
    MENOR (<), MAYOR (>), DESPLAZAR_IZQ (<<), DESPLAZAR_DER (>>), IGUALDAD (==),
    DIFERENTE (!=), MENOR_IGUAL (<=), MAYOR_IGUAL (>=), AND_LOGICO (&&), OR_LOGICO (||).
- Literales: NUMERO_ENTERO (números enteros), IDENTIFICADOR (identificadores de variables/funciones),
  LITERAL_CADENA (cadenas entre comillas dobles), LITERAL_CARACTER (caracteres entre comillas simples).
- Control: FIN_ARCHIVO (Fin de archivo) y ERROR (Error léxico por símbolo no válido).


------------------------------------------------------------------------
B. Clase `Token` (Token.java)
------------------------------------------------------------------------
Representa una unidad léxica o token producido por el lexer.

Atributos:
- `tipo` (TipoToken): El tipo al que pertenece el token.
- `lexema` (String): La secuencia exacta de caracteres del código fuente.
- `linea` (int): Número de línea donde fue encontrado.

Métodos:
- `Token(TipoToken tipo, String lexema, int linea)`: Constructor que inicializa los campos.
- `obtenerTipo()`: Devuelve el tipo del token (`TipoToken`).
- `obtenerLexema()`: Devuelve el texto del lexema (`String`).
- `obtenerLinea()`: Devuelve la línea donde inició el token (`int`).
- `toString()`: Formatea el token para imprimirlo en pantalla según el formato
  requerido: `Token: TIPO "lexema"`.


------------------------------------------------------------------------
C. Clase `Main` (Main.java)
------------------------------------------------------------------------
Punto de entrada de la aplicación. Maneja la interacción con el sistema operativo
y el archivo de entrada.

Métodos:
- `main(String[] argumentos)`:
  1. Verifica que se haya pasado la ruta del archivo como argumento.
  2. Lee el contenido del archivo utilizando `Files.readString(Path.of(argumentos[0]))`.
  3. Instancia el `Lexer`.
  4. Ejecuta un bucle `while (true)` que llama a `lexico.siguienteToken()`.
  5. Procesa los tokens: imprime tokens válidos, acumula y muestra errores léxicos,
     y detiene el bucle al recibir `TipoToken.FIN_ARCHIVO`.


------------------------------------------------------------------------
D. Clase `Lexer` (Lexer.java)
------------------------------------------------------------------------
Clase principal que implementa el analizador léxico mediante el autómata determinista.

Estructura Interna y Atributos:
- Constantes `CLS_*` (0 a 26): Representan la columna en la tabla de transiciones
  para cada categoría de carácter (ej. letras, dígitos, comillas, símbolos).
- Constantes de Estados (`INICIO`, `ESTADO_ID`, `ESTADO_NUM`, etc., y `MUERTO` = -1):
  Representan las filas de la tabla de transiciones.
- `tabla[][]` (int[40][27]): Matriz bidimensional que almacena la función de transición.
- `aceptacion[]` (TipoToken[40]): Arreglo unidimensional que mapea cada estado final/de
  aceptación con su correspondiente `TipoToken`.
- `PALABRAS_RESERVADAS` (Map<String, TipoToken>): Tabla hash estática para mapear lexemas de
  palabras clave (ej: "if", "return", "int") a su `TipoToken` específico.
- `fuente` (char[]): Código fuente convertido en un arreglo de caracteres.
- `posicion` (int): Índice del carácter actual en `fuente`.
- `linea` (int): Número de línea actual en el análisis.
- `longitud` (int): Tamaño total del código fuente.

Métodos:
- `construirTabla()` (privado y estático):
  Construye explícitamente la matriz `tabla[][]` y el arreglo `aceptacion[]`. Define las
  reglas del AFD para identificar números, cadenas, caracteres, identificadores y operadores.

- `clasificar(char c)` (privado y estático):
  Recibe un carácter y retorna el número de columna (clase `CLS_*`) correspondiente.

- `Lexer(String fuente)` (constructor):
  Inicializa el arreglo de caracteres `fuente`, la posición en 0 y la línea en 1.

- `echarVistazo()` (privado):
  Retorna el carácter actual en `posicion` sin avanzar el puntero (o '\0' si es fin de archivo).

- `echarVistazoSiguiente()` (privado):
  Retorna el carácter siguiente (`posicion + 1`) sin avanzar el puntero.

- `avanzar()` (privado):
  Consume el carácter actual, avanza `posicion` y, si encuentra un salto de línea ('\n'),
  incrementa el contador `linea`.

- `estaAlFinal()` (privado):
  Indica si se ha llegado al final del arreglo de entrada (`posicion >= longitud`).

- `omitirEspaciosYComentarios()` (privado):
  Avanza el puntero omitiendo caracteres invisibles y comentarios (`//` y `/*...*/`).

- `siguienteToken()` (público):
  Llama a `omitirEspaciosYComentarios()`, mide la línea inicial y ejecuta `escanearConTabla(lineaInicio)`
  para retornar el siguiente `Token`, o `TipoToken.FIN_ARCHIVO` si ya no hay más caracteres.

- `escanearConTabla(int lineaInicio)` (privado):
  Ejecuta la simulación iterativa de la tabla de transiciones con retroceso ("maximal munch").
  Retorna el `Token` reconocido o un token de `ERROR` si no hubo coincidencia.
